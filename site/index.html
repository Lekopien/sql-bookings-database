A bookings database, live in your browser

A normalised SQLite schema for a studio that sells services by appointment. Triggers block double-booking and overpayment, views compute balances, and the reports use window functions and recursive CTEs. The real database runs below via WebAssembly.

trigger no_overlap      a staff member can't be double-booked
trigger no_overpay      payments can't exceed the balance

Integrity in the database

CHECK constraints, foreign keys with cascades, unique case-insensitive emails and triggers, so bad data can't get in from any app.

Versioned migrations

Numbered SQL files applied once each, in a transaction, tracked in schema_migrations.

Analytical SQL

Running totals with SUM() OVER, LAG for month-over-month change, RANK, pivots and a recursive slot calendar.

Indexed for the queries

Composite (staff_id, starts_at) index; a test asserts the query planner uses it.
